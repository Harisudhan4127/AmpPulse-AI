# API Specification

Base URL (local dev): `http://<laptop-local-ip>:8000`
All bodies are JSON. All error responses use the envelope:
```json
{"success": false, "error": {"code": "SOME_CODE", "message": "Human readable message"}}
```

Interactive docs are auto-generated by FastAPI at `/docs` (Swagger) and `/redoc`.

## Authentication
Two independent schemes:
| Caller   | Header                          | Obtained via |
|----------|----------------------------------|--------------|
| Frontend (user) | `Authorization: Bearer <jwt>` | `POST /api/v1/auth/login` |
| ESP32 (device)  | `X-Device-Key: <key>`          | `POST /api/v1/devices/register` (once) |

---

## `GET /api/v1/health`
Health check. No auth.
- **200** `{"success": true, "status": "ok", "server_time": "<iso8601>"}`

---

## `POST /api/v1/auth/login`
User login → JWT.
- Auth: none
- Body: `{"email": "demo@amppulse.ai", "password": "Demo@12345"}`
- **200**
```json
{"success": true, "access_token": "<jwt>", "token_type": "bearer",
 "user": {"id": 1, "email": "demo@amppulse.ai", "role": "home"}}
```
- **401** `AUTH_FAILED` — invalid email or password

---

## `POST /api/v1/devices/register`
One-time device provisioning. Issues the device's permanent API key.
- Auth: `X-Provision-Key: <DEVICE_PROVISION_KEY from backend .env>`
- Body:
```json
{"device_id": "ESP32_001", "name": "Home Energy Monitor", "firmware_version": "1.0.0"}
```
- **201**
```json
{"success": true, "device_id": "ESP32_001", "device_key": "dvk_...",
 "message": "Store this device_key securely on the device. It will not be shown again."}
```
- **401** `UNAUTHORIZED` — bad/missing provisioning key
- **409** `DEVICE_ALREADY_EXISTS`
- Timeout/retry: none needed — this is a manual, one-time operation.

---

## `GET /api/v1/devices`
List devices belonging to the current user (frontend).
- Auth: user JWT
- **200** `{"success": true, "devices": [ {device_id, name, is_active, firmware_version, last_seen_at, status, channel_labels}, ... ]}`
  - `status` is derived: `"online"` if `last_seen_at` within `DEVICE_OFFLINE_AFTER_SECONDS` (default 90s), else `"offline"`.

## `GET /api/v1/devices/{device_id}`
- Auth: user JWT
- **200** `{"success": true, "device": {...same shape as above...}}`
- **404** `DEVICE_NOT_FOUND`

## `GET /api/v1/devices/{device_id}/status`
- Auth: user JWT
- **200**
```json
{"success": true, "device_id": "ESP32_001", "status": "online",
 "last_seen_at": "2026-09-06T05:35:26Z",
 "latest_reading": {"voltage":230.5,"current":2.1,"power":483.5,"energy_kwh":12.34,
                     "frequency":50.01,"temperature":28.4,"humidity":62.1,
                     "channel_status":{"1":"ON","2":"OFF"},"created_at":"..."}}
```
- **404** `DEVICE_NOT_FOUND`

## `PATCH /api/v1/devices/{device_id}/channels`
Rename appliance channels.
- Auth: user JWT
- Body: `{"channel_labels": {"1": "Air Conditioner", "2": "Fan"}}`
- **200** `{"success": true, "device": {...}}`
- **404** `DEVICE_NOT_FOUND`

---

## `POST /api/v1/devices/{device_id}/data`
ESP32 pushes one telemetry reading.
- Auth: `X-Device-Key`
- Headers: `Content-Type: application/json`
- Body:
```json
{
  "device_id": "ESP32_001",
  "timestamp": 1757146200,
  "voltage": 230.5,
  "current": 2.1,
  "power": 483.5,
  "energy_kwh": 12.34,
  "frequency": 50.01,
  "power_factor": 0.95,
  "temperature": 28.4,
  "humidity": 62.1,
  "channel_status": {"1": "ON", "2": "OFF"},
  "status": "online"
}
```
- Validation ranges: voltage 0–400V, current 0–100A, power 0–20000W,
  frequency 0–100Hz, power_factor 0–1, temperature -40–125°C, humidity 0–100%.
  `channel_status` values must be `"ON"` or `"OFF"`.
- **201** `{"success": true, "received_at": "<iso8601>", "reading_id": 1}`
- **400** `DEVICE_ID_MISMATCH` — body device_id ≠ URL device_id
- **401** `UNAUTHORIZED` — bad device key
- **404** `DEVICE_NOT_FOUND`
- **422** `VALIDATION_ERROR` — out-of-range or malformed field
- **Timeout/retry (ESP32 side)**: 4s request timeout; on failure, ESP32
  backs off exponentially (see esp32-firmware/README.md), capped at 6× the
  base telemetry interval, and resets on next success.

## `GET /api/v1/devices/{device_id}/data?limit=100`
Frontend reads recent history (for charts/tables).
- Auth: user JWT
- Query: `limit` (1–2000, default 100)
- **200** `{"success": true, "device_id": "...", "readings": [ {voltage, current, power, energy_kwh, frequency, power_factor, temperature, humidity, channel_status, created_at}, ... ]}` (oldest→newest)
- **404** `DEVICE_NOT_FOUND`

## `GET /api/v1/devices/{device_id}/summary?days=7`
Cost/bill summary for dashboard KPIs.
- Auth: user JWT
- **200**
```json
{"success": true, "device_id": "ESP32_001",
 "today_energy_kwh": 3.2, "today_cost": 19.2, "projected_month_cost": 576.0,
 "daily": [{"date": "2026-09-06", "energy_kwh": 3.2, "estimated_cost": 19.2}]}
```
- **404** `DEVICE_NOT_FOUND`

---

## `POST /api/v1/devices/{device_id}/commands`
Frontend queues a relay command.
- Auth: user JWT
- Body: `{"action": "relay_set", "channel": 1, "value": "OFF"}` (`channel`: 1–2, `value`: ON/OFF)
- **201** `{"success": true, "command": {"id":1,"action":"relay_set","channel":1,"value":"OFF","status":"pending","created_at":"..."}}`
- **404** `DEVICE_NOT_FOUND`
- **422** `VALIDATION_ERROR`

## `GET /api/v1/devices/{device_id}/commands`
ESP32 polls for pending commands. Marks returned commands `delivered`.
- Auth: `X-Device-Key`
- **200** `{"success": true, "commands": [{"id":1,"action":"relay_set","channel":1,"value":"OFF","status":"delivered","created_at":"..."}]}`
  (empty array if nothing pending)
- **401** `UNAUTHORIZED`
- **404** `DEVICE_NOT_FOUND`
- **Retry behavior (ESP32 side)**: polled every 3s regardless of prior
  success/failure — no special backoff needed since this is a lightweight,
  idempotent GET.

## `POST /api/v1/devices/{device_id}/commands/ack`
ESP32 confirms it applied (or failed to apply) a command.
- Auth: `X-Device-Key`
- Body: `{"command_id": 1, "status": "acked"}` (or `"failed"`)
- **200** `{"success": true, "command_id": 1, "status": "acked"}`
- **404** `COMMAND_NOT_FOUND`

## Error codes reference
| Code | HTTP | Meaning |
|------|------|---------|
| `VALIDATION_ERROR` | 422 | Request body failed schema/range validation |
| `UNAUTHORIZED` | 401 | Missing/invalid auth header or key |
| `INVALID_TOKEN` | 401 | JWT expired or malformed |
| `AUTH_FAILED` | 401 | Wrong login credentials |
| `DEVICE_NOT_FOUND` | 404 | device_id doesn't exist |
| `DEVICE_ALREADY_EXISTS` | 409 | Duplicate registration attempt |
| `DEVICE_DISABLED` | 403 | Device soft-disabled by admin |
| `DEVICE_ID_MISMATCH` | 400 | Body/path/header identity mismatch |
| `COMMAND_NOT_FOUND` | 404 | command_id doesn't exist for that device |
| `INTERNAL_ERROR` | 500 | Unhandled server error |
